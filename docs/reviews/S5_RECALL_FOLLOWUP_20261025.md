`s5-recall-20261025-ranking-before.json` 记录所有题的期望条款及前五候选的四路排名。十五条未命中均有可用原文，不是缺文件：问题正文通道权重 3.0，维度正文 1.0、标题 0.5；中文业务泛词、填充描述及机翻正文前 180 字的“伪标题”压过了直接规范标题。RRF 丢失匹配强弱，微弱匹配也能取得完整路线权重。

只读实验表明，简单调整标题权重或加一套术语概念特征不能同时改善五国，未进入运行代码。被否决的术语实验记录为 `s5-recall-20261025-retrieval-probe.json`：9/32，新加坡 4/8、突尼斯 2/6，其余国家下降；不能作为交付结果。

## 阶段一：可配置查询规划与候选重排

保留原稀疏路线，在现有检索工具内按配置选择是否启用查询规划。规划器根据实际问题、维度和来源语言生成最多六个检索词组，合并原路线与多语言路线，再对有限候选池排序。重排只能选择池内 ID，重复、越界、空选或超出 top_k 均拒绝并明确记录降级到原稀疏路线。原文、来源、法域、版本、页级隔离和数字/逐字校验不改变；窗口预览仅用于排序，保留原始偏移，不充当引文。

此能力复用现有模型接口，不安装重型检索框架。新增的模型调用、查询、候选池、输出、已知 Token、错误及降级均进入工具轨迹和评测成本。新增运行协议 `s5-planned-retrieval-v3`；检索节点模型、温度、提示词及 `semantic_planning` 是实际执行参数，代码入口与工具/拓扑仍不可修改。默认关闭，须导入新版本并显式激活；历史运行及历史配置保持原样，不追填执行版本。

阶段一回归：44 项通过，包含配置驱动、越界/重复 ID 拒绝、四种来源语言、精确原文窗口及原有十二项反例。真实质量评测另行追加，工程测试通过不能代替召回和语义质量验收。

## 阶段二：就绪核验、跨语言边界与格式失败

有候选却无结论、模型报错不再被核验跳过。增加独立 `readiness_items`，与逐字引文核验分开记录；具体原因进入原有最多两轮退回，耗尽后仍阻断报告，不把失败伪装成法源不足。集成回归验证首次“缺定义”轨迹被保留，且只退回缺结论的维度。

列表与例外检测可以识别前导 RTL 方向符号，引用仍直接截取原文且保持原偏移。生成阶段收到实际问题，不再只收到可能与具体问题不同的维度标题；一般规则不能被称作已经解决专门汽车分类。提示词强调主体、所有格、行为对象、引用层级和例外的对应，不放宽数字或原文校验。

第一轮真实执行还暴露了独立 Judge 返回额外 JSON 字段。新处理仍拒绝该输出，只对格式/索引问题最多重试一次，保留原始无效输出和费用；合法的 no/partial 不重试。Judge 判据及提示词哈希保持 `01793fddab716693d4b5eb7e5f1272768f93edc5cc5a857435d9f0539a6bc6f3`。

候选池增加独立真实标题路线，并按查询路线覆盖后再排序填满，避免多个相关改写挤走另一条查询路线；不是按国家或法规配额。新运行协议 `s5-query-routes-v4` 与旧规划输出协议分开，必须显式导入/激活。画布中启用规划的检索节点提示词标为实际模型提示词。

回归分批通过：74 项（包含十二项反例）、新增空维度回退等 19 项、格式与 Judge 判据回归 26 项；两轮全后端回归分别 358、359 项通过。最终代码的完整回归和真实质量/稳定性数字在完成后追加，不能用这些中间测试结果冒充最终验收。

## 阶段三：检索失败格式与预算整改

v31 完整真实批次为 28/32 命中、59/75 程序核验、55/57 独立 Judge 支持、8 题技术错误；v33 为 29/32、68/81、64/68、7 题技术错误。这些均保留，不能因支持率高就隐去未产出项和失败。v33 的 1500-token 重排预算出现截断，且有池外 ID；这是调用配置和格式问题，不能当成法源缺失。

为规划与重排发送实际 Pydantic Schema，重排 Schema 限定候选 ID 枚举与数量；仍在程序端独立校验。只对 Schema/ID 格式错误增加一次纠正，原始输出、原因、费用保留；合法的语义拒绝不重试。提高输出预算以容纳推理模型的推理 Token，未降低任何校验。规划可查看有界的原文标题词汇表，不靠法规名或评测 ID 提示答案；资料增加时按预算和通用相关性选取标题。检索失败仍保留已知查询及候选池，旧批次未记录的候选池标为未知，不能倒推成真实未召回。
