# 法规库按国家与文件层级展开：修改与验证记录

日期：2026-10-24。分支：`codex/remediate-s0-s3-s1-s2`。

## 展示调整

用户端“法规知识库 → 法规原文”和管理端“法规文档”都接入了三级折叠目录：

```text
国家
  └─ 文件层级（已有文档类型）
       └─ 法规文件
```

- 一次展开一个国家和一个文件层级，支持再次点击收起；未展开的文件不渲染成长列表。
- 文件层级按已有类型排序：法律、法规与实施规则、监管指南与框架、标准、申报表与材料、其他文件。分类不读取标题推测等级，不改写类型和法律效力；自定义类型及未知类型仍保留可见。
- 每个层级的目录文件每页 8 份，长名称最多显示三行，可悬停查看全名；同名不同文件分开保留并显示短编号。
- 用户端选择文件继续展示原有官方来源、版本、原文/译文、合规属性和关联图谱；选择文件后自动展开所在层级并定位其目录页。
- 用户端移除原先的国家卡片横排和不折叠的长目录；法规原文通过国家目录切换，图谱与条款检索标签保留紧凑的国家选择框。
- 管理端选择国家及层级后，右侧只显示该组文档，每页 20 份；保留原有状态、来源隔离标识、相关性调整、翻译、上传和版本抽屉入口。增加已加载文档的名称/来源搜索，筛选变化后重置分页。
- 管理端首次使用原接口加载最多 200 份文件；如仍有后续批次，明确显示“继续加载文档”及已加载范围，不把前 200 份冒充完整库。后续批次使用首次查询的国家/站点条件，避免编辑筛选框后把两次查询混在一起。本地实际库 80 份，未触发下一批按钮，未构造测试文档污染业务库。

共享纯函数位于 `packages/shared/src/regulationDirectory.ts`。两端目录组件保持一致，并有回归测试检查一致性。没有新增依赖，没有修改后端、采集、解析、翻译、审批规则、数据库表或报告引用。
