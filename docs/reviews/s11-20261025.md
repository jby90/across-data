## 发现与处理

- 手点首次续跑被原文完整性检查拦住。原因是 S10 合成夹具误把两份 PDF 写到另一个临时归档根目录，不是 RLS 误拦。按数据库记录的 SHA-256 和文件长度核对已有字节后，仅补回演示目录中缺失的两份相同文件；未覆盖既有文件、未改数据库行、未降低任何校验。[恢复记录](s11-20261025-archive-fixture-recovery.json)、[当时的失败状态](s11-20261025-ui-admin-failure-preserved.png)。
- 随后在同一任务中重试成功，原来的失败轨迹保留。实际任务的分析请求为第一次 D1–D8、续跑仅 D3；30 条聊天消息、13 条轨迹、1 份报告归属同一企业。部署前须对真实归档目录执行完整文件/哈希预检。
- 回环 pgserver 的 trust 认证不等于生产密码认证测试；后者须在真实 Docker/服务器环境验证。生产 API/worker 不能使用迁移所有者，迁移与启动分离已进入配置，整栈实跑在 S12 完成。
- 手点还发现，从带任务 query 的页面新建对话后，URL 仍保留旧任务 query，而当前界面显示新任务。没有跨企业泄露或记录错写；这一导航一致性问题记录为 S12 部署前修正项，不更改原任务/报告。

后续继续 S12 交付件与部署、S13 总验收；真实资料人工核对、来源条款确认、金标确认仍不自动通过。
