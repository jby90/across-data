## 一、需要优先处理的缺陷

### R1 / P1：翻译预处理改写历史条款与证据

位置：[cli.py:227](E:/汽研项目/CrossBorderPlatform/backend/app/cli.py:227)、[cli.py:264](E:/汽研项目/CrossBorderPlatform/backend/app/cli.py:264)。

`batch_translate()` 首先调用 `_split_oversized_clauses_for_country()`。后者直接把已有 `Clause.original_text` 改为首个分块，更新原文哈希，并把后续分块作为同一版本的新 Clause 追加，生成 `.1` 等新编号。已有边的引文如果无法在任一分块中找到，还会替换成首块前 240 字，而没有重新审定关系或取消原批准状态。

隔离复现结果：`original_unchanged=False`、`hash_unchanged=False`、`edge_quote_unchanged=False`；测试输入是原本真实存在、跨分块边界的引文。这使得旧条款 ID、人工复核与历史报告所依赖的内容发生变化，原编号和展示顺序也可能变化。归档原文件仍在，但数据库里的历史引用对象已不再稳定。

建议：翻译分块只作为计算过程中的临时片段。重新解析应生成有记录的解析修订/映射，保留旧条款与证据；无法定位的引文标记失效并退回核对，不能替换成另一段原文。修复前不要再次全库执行当前翻译 CLI；数据修复应先备份并另行确认范围。

### R2 / P1：分析工具仍返回已作废、已驳回、已失效的图谱边

位置：[tools.py:339](E:/汽研项目/CrossBorderPlatform/backend/app/analysis/tools.py:339)。

`ToolBox.query_kg_obligations()` 只按条款 ID 查边，没有过滤 `superseded/rejected/stale`，关联节点也没有状态过滤。三种状态分别建立测试，三种都被返回。图谱页面已隐藏旧边，并不意味着工具调用已经隔离旧边。

影响边界：当前 [pipeline.py:327](E:/汽研项目/CrossBorderPlatform/backend/app/analysis/pipeline.py:327) 调用了该工具，但没有接收返回值。因此可以确认工具返回和轨迹统计不干净，**不能据此声称这些旧边已经进入当前报告的模型提示词**；同时也说明图谱结果尚未在该处形成实际分析输入。这一集成问题需要后续编排工作共同处理。

建议：工具层与用户图谱使用统一的活跃状态过滤；结构边、待核对语义边、人工确认语义边分别输出。真正接入分析前先通过状态过滤反例。

### R3 / P1：语义裁判不可用时会以规则结果放行

位置：[extractor.py:988](E:/汽研项目/CrossBorderPlatform/backend/app/knowledge/extractor.py:988)、[extractor.py:1001](E:/汽研项目/CrossBorderPlatform/backend/app/knowledge/extractor.py:1001)。

`_call_llm_judge()` 超时、异常或返回非 200 时得到 `None`；`judge_extracted_relation()` 随后返回确定性规则结果。这套规则主要检查谓词，可能给出 `yes`，之后按“语义核验通过”入库。

隔离反例：原文只说“An organisation must protect personal data.”，目标却设为“Delete all recordings within 30 days”。模拟裁判不可用后，系统返回 `admitted=True`、`judge_verdict=yes`，理由还声称证据明确支持该义务。

建议：裁判不可用单独标为 `unjudged/error`，保留待重试候选，不进入已通过语义核验的活跃图。记录裁判来源、模型、提示词版本和调用状态；质量统计必须能区分规则检查与模型裁判。

当前 428 条语义边的理由未命中规则兜底的固定前缀，本次没有证据断言它们全部走过此故障路径。这里指出的是已经复现的故障处理缺陷；`semantic_unjudged=0` 本身不足以证明该路径安全。

### R4 / P1：数字、百分比和币种改错仍可能通过翻译校验

位置：[translator.py:46](E:/汽研项目/CrossBorderPlatform/backend/app/knowledge/translator.py:46)、[translator.py:284](E:/汽研项目/CrossBorderPlatform/backend/app/knowledge/translator.py:284)。

数字检查使用字符串包含，而不是完整数值匹配；百分号正则的末尾词边界还可能使 `%` 被丢掉；币种没有参与数值校验。

三项反例均被判定合格，`quality_issues=[]`：

| 原文中的值 | 错误译文 | 当前结果 |
| --- | --- | --- |
| 金额 `10`、期限 `5 days` | `100元`、`50天` | 通过 |
| `10%` | 只写 `10`，丢失百分比单位 | 通过 |
| `$500` | `500欧元` | 通过 |

以上为合成测试句，不是对实际法规金额的法律判断。建议使用完整数值 token、数量与单位组合校验，处理合法的千分位、阿拉伯数字及中文单位写法；遇到歧义转人工。数字检查仍不能代替语义忠实度核查。

### R5 / P1：重抽取能修改已批准边的证据，保留旧批准状态

位置：[extractor.py:1563](E:/汽研项目/CrossBorderPlatform/backend/app/knowledge/extractor.py:1563)。

`_upsert_edge()` 找到已有非 superseded 四元组时，会覆盖引文、抽取模型、置信度、裁判结果等，但不重置 `review_status/reviewed_by/reviewed_at`。重跑前的 supersede 又特意不处理 approved 边，因此存在“新证据继承旧批准”的路径。

隔离复现：一条 approved 边的引文从保护个人数据变成通报泄露，更新后仍为 approved。这里验证的是审批与证据绑定的完整性，并非断言实际库已发生相同改写。

建议：人工批准绑定不可变的证据、条款版本及内容哈希。新结果有实质变化时生成 pending_review 修订，保留旧批准快照，不在原行上覆盖。

### R6 / P1：重建失败会撤下旧的待复核语义图谱，并返回成功

位置：[extractor.py:1820](E:/汽研项目/CrossBorderPlatform/backend/app/knowledge/extractor.py:1820)、[extractor.py:2277](E:/汽研项目/CrossBorderPlatform/backend/app/knowledge/extractor.py:2277)。

重抽取开始前先把待复核语义边全部 supersede。随后即使模型抽取全部返回 `None`，流程仍继续提交结构边，最后正常返回；旧 pending_review 语义边已经不可见。

隔离复现：原有 1 条 pending 语义边；模型全部不可用后返回 `semantic_edges_added=0`，原边变成 superseded。不是抛异常回滚的路径，而是“空结果当成功提交”的路径。

建议：按抽取批次暂存新结果，完整记录失败、空结果、零关系等不同原因；成功并通过检查后才原子切换活跃批次，失败时保留上一可用图谱。

### R7 / P1：`--only-missing` 只补抽样集合，不补全缺失译文

位置：[cli.py:391](E:/汽研项目/CrossBorderPlatform/backend/app/cli.py:391)、[cli.py:424](E:/汽研项目/CrossBorderPlatform/backend/app/cli.py:424)。

CLI 目标集合是“原来已有译文 / 被边或解读引用 / 核心文档前 N 条”。新加坡只取前 8 条，其他国家前 15 条；其余没有引用关系的未译条款不会进入任务集合。当前还只把 `relevant` 文件纳入这部分抽样，没有完整覆盖新增的 `related` 层级。

隔离复现：一份 20 条的新加坡核心文件，模型全部可用，执行 `only_missing=True` 后仅完成 8/20，统计仍是成功 8、失败 0。

建议：明确完整翻译与演示抽样两种作业模式；完整模式枚举目标范围内最新版本的所有条款，并带分页/断点/失败重试。统计分别展示总目标、合格、失败、未执行、范围外，而不是只计算已进入任务集合的成功率。

### R8 / P1：节点八项属性仍按国家硬编码，能给范围外文件填入无依据结论

位置：[router.py:138](E:/汽研项目/CrossBorderPlatform/backend/app/knowledge/router.py:138)、[router.py:174](E:/汽研项目/CrossBorderPlatform/backend/app/knowledge/router.py:174)。

`_compute_eight_attributes()` 根据国家和少量标题条件填入跨境条件、留存年限、罚款、准入材料等固定文案，并覆盖/合并到节点输出属性。它不要求这些结论来自本节点的条款证据。

隔离测试及当前 API 均已复现：`Courts (Civil and Criminal Justice) Reform Act 2021` 节点虽标 `out_of_scope`，仍带有 PDPA 跨境要求、自动驾驶记录留存和 PDPC 罚款等属性。错配语义边被移除后，属性展示路径仍会产生误导。问题在于来源关联不成立，本报告不对这些固定文案的法律准确性作判定。

建议：八项属性逐项绑定原文依据、版本和复核状态；没有对应依据时返回空值/待核查，范围外文件不生成业务合规结论。国家概览如需保留，应作为单独、有依据的概览资料展示。
