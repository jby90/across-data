# 历史来源错绑提示修复

## 原因与处理

图谱原先只统计仍被隔离的文件数。旧 PDPA 条目错误绑定 44 页 LTA 自动驾驶申请资料，正确的 125 页官方历史修订版已独立归档，并有不可变的来源替代关联。旧记录必须继续隔离，因此原计数始终为 1，页面持续显示红色告警，无法区分“尚未找到正确原文”与“已有关联替代原文”。

新增只读状态投影，不修改原文、审批、隔离提议或审计：

- 替代关联的审计摘要、文档/版本/国家对应、来源地址、归档哈希/字节数和登记封面依据均匹配，且替代版本当前可用时，列为“历史来源记录”，默认折叠。
- 缺少或损坏归档、替代文件被隔离或驳回、跨国家错连、版本已变化、关联摘要被篡改时，继续显示“待补充正确原文”。
- 管理员可分别打开替代原文和旧记录。文档页支持按 ID 直接定位，不依赖文件恰好在首批列表。
- 旧记录的 `safety_hold` 保持生效，仍不能进入检索、翻译、报告依据或被审批为法律依据。替代关联不继承人工批准，也不把历史版本认定为现行法律。

算法根据来源记录和状态判断，不使用特定国家、法规标题、文档 ID 或样本数量作为成功分支。

## 验证

- 线上只读探针识别到 1 条 `replacement_available`，旧文件仍隔离；替代版本仍为 `pending_review / unknown`。
- 后端来源状态、来源隔离、规范绑定、原 12 项反例、图谱及用户展示相关回归：41 项通过。
- 前端图谱展示、分组、法规目录和术语相关测试：34 项通过；管理端类型检查与 `/admin/` 生产构建通过；Ruff 与差异检查通过。
- 上线前已备份数据库，并记录 11 张原文、证据、隔离提议、术语和审批相关表的行数及整行摘要。部署后另附生产校验与截图。
