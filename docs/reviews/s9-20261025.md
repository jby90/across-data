# S9 引用复核策略与报告状态

用户已确认默认采用 `allow_machine_with_notice`：机器处理内容可以进入草稿，逐条标记待核对。没有执行真实资料的人工批准。

## 改动与边界

- 服务配置 `CYSH_CITATION_POLICY` 支持允许机器草稿与 `reviewed_only` 两种模式；管理端显示只读策略，不能在线关闭校验。
- 严格模式同时要求原文版本已批准、条款无需复核，以及合格现行译文已批准。中文原文无需另做中文翻译。原文被拒绝、译文不合格、现行译文冲突、来源隔离、过期或废止等原有闸门继续生效。
- 原文和译文的批准状态分开记录；仅有“译文 approved”不等于原文或法律结论已复核。多个现行译文不随意选取，保留冲突并提示待核对。
- 任务和新报告记录生成时策略。追问续跑沿用已记录策略；编辑报告复制原策略。旧报告字段为空，不回填、追认或改写历史审批。
- 严格模式在编制前重新检查候选的复核/版本状态，并在保存报告的事务内使用共享锁；锁内不调用模型、不等待用户回答。分析中发生撤回的候选不能继续生成严格报告。
- 报告顶部、引用角标、引用抽屉及整份/章节 Word/PDF 均区分程序核验与人工复核。概览按条款、版本、译文版本去重，并给出引用处数。历史缺少原文审批快照的引用保守标记待核对，原始快照保持不变。
- 去掉“所有引用均为官方原文”的无条件摘要；逐条展示来源性质。Word 章节标题与引言避免落在页尾而正文独自进入下一页。
