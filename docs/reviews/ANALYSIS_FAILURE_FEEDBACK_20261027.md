## 修改范围

- 补证请求增加显式 `repair_budget`：本轮允许的新项目上限、可处理的事实键、系统已保留内容不应重写，以及无法补证时使用空结果和具体缺口的要求。在没有保留项的补证请求中同样提供。
- JSON Schema 的 `maxItems` 和程序端数量校验保持原样；校验失败反馈包含本轮允许数量与实际数量。超量结果仍拒绝，不截断、不降低语义或引文要求，不扩大重试轮数。
- 用户详情增加只读计算字段 `failure_summary`：按已保存结果列出格式失败、超时或依据未通过完整核验的维度；显示保留引用数量和下一步操作。只读取必要字段，不复制模型提示词或整份工具载荷，不返回原始异常、模型参数、调用日志或提示词。
- 重试进度只显示最新一轮的阶段，管理端历史轨迹继续完整保留。报告编制轨迹不再把 `analysis_failed` 描述为可交付的部分样稿。
- 用户端直接展示原因分类；未通过的报告，其章节导出按钮与整份导出保持相同禁用条件。导出接口原有保护不变。

没有修改任务、报告版本、原文、条款、证据或审批记录；本次不将真实失败结果改写成成功，也不自动发起付费模型重试。提示词强化不等于已证明真实模型后续一定遵守；程序拒绝超限输出的检查继续保留。
