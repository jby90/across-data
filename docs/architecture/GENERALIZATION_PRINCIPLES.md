# 通用性原则与扩展验收

用户要求：机制和算法面向持续增加的国家、法规及文档格式，不能靠对某国或某部法规的特判过关。

## 核心边界

1. **共享流程**：采集发现、归档去重、解析、翻译、抽取、证据核验、检索、智能体交接和报告使用共同接口、数据结构及状态机。
2. **差异进入配置或适配器**：官方域名、抓取条款、语言/OCR 参数、当地术语定义、文档类型映射属于国别/来源配置；不同编号体系、扫描版式、表格/续表属于按内容特征识别的格式适配器。
3. **法律事实来自本地法域原文**：相同术语不意味着相同定义或义务。条款、日期、适用条件、例外、罚则和报告结论必须绑定国家、原文版本、出处及证据；缺失时待核查。
4. **修原因而非修答案**：新格式失败应改相应解析/核验规则，增加其他文档的正反例。不能用法规标题、文档 ID、固定条号、期望译文或当前数量选中“成功”分支。
5. **保护历史**：错绑/历史损坏的受控修复清单可以按 ID 或哈希精确定位，但不能变成日常解析算法。旧原文、证据、批准/驳回和修复审计保留。
6. **业务试点不充当算法白名单**：首批试点继续是新加坡、埃及、突尼斯、摩洛哥、黎巴嫩；新增国家可以被元数据发现。被发现不代表已有官方文本、可抓取、数据齐全、可以正式引用或完成验收。

## 本次已落实（2026-10-24）

- 图谱按文档身份与证据来源归组，布局按节点/分组集合计算，不依赖国名、法规名称或当前五国的文件数量。共享实体只绘制一次；同名不同文件不合并。
- 总览成员按归属一次分桶，避免每增加一部法规就重复扫描全部节点；同一文档有多个法规节点时也保持固定范围排布。
- 目录根据实际国家、文档类型和文件集合生成；未识别的文档类型仍可见，名称可由配置提供，缺失/冲突时显示代码。
- 管理端图谱国家选项改为只读接口发现已有来源配置、文档与图谱记录中的国家，删除页面内写死的五国选项。
- 用户端知识库统计覆盖有可见文档的新国家，并保留原五国空库入口。来源隔离规则照常生效，只有被隔离文档的新国家不会因统计发现而暴露给用户端。
- 国家统计改为批量聚合，查询次数不随国家数逐国增长；既有五国结果和上一提交的旧实现逐项一致。
- 解析修复候选查询不再使用五国正则白名单，仍要求两字母代码、管理端权限与原审计哈希核验。
- 新国家显示名称可放在来源 `config.country_name_zh`、`config.country_name_orig`；不配置则显示代码。多个来源名称冲突时不猜测，使用代码。
- 国家发现、统计、展示不会启用来源、执行抓取/模型抽取、放宽证据闸门或自动批准任何结果。

## 持续扩展的验收条件

新增国家以数据接入为主：注册来源及元数据 → 取得采集授权 → 官方资料归档 → 结构与语言验证 → 引文/数字/版本核验 → 检索及报告测试 → 人工复核。

修改通用机制时，至少验证：

- 非当前试点国家和未知名称/类型；多语言及 RTL 文本。
- 同名文件、多个版本、缺元数据、空库、来源隔离、证据不足等负例。
- 调换国名/法规标题不改变算法选择或自动产生法律结论。
- 文件数量增加、大小法规混合时不截断后续文件；批准/待核对/驳回不因重新处理被篡改。
- 无有效证据时仍阻断正式结论；页面展示成功不能代替法律验收。
- 在独立测试库或内存中验证；记录真实数据测试与合成数据测试的范围，不能混用。

## 后续需要继续统一的旧入口

本次是通用性约束落地与国家浏览入口整改，不等于已完成整个平台的任意国家验收。

- `backend/app/analysis/chat.py` 的事实收集仍使用 `COUNTRY_NAMES_ZH` 五国枚举。后续应接统一国别配置与分析就绪状态，连同会话恢复、缺证据阻断、八维报告回归一并迁移；不能仅删除名单就宣称新国家已可分析。
- 官方网站专用采集适配器、国别术语种子应逐项区分“必要的来源差异”和“可抽象的结构规则”。增加新格式时按特征复用适配器，不能复制某国整条流水线。
- 数万法规下的检索、图谱渲染、存储与任务并发还需真实规模测试；本次合成测试验证通用计算与发现逻辑，不是生产容量证明。

当前规则同步写入仓库根目录 `AGENTS.md`，供后续开发持续执行。
