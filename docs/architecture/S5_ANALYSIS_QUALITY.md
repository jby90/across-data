启用 `semantic_planning` 时，检索节点复用现有模型接口，先规划目标来源语言的短查询，再对有界候选池重排。原稀疏路线与独立原文标题路线共同产生候选；原文标题词汇表来自实际候选元数据、受字符预算约束。模型不能选择池外条款；失败可见且保留查询、候选池、无效输出、重试及费用。该能力只改候选排序，不生成法律证据，不修改人工审批。生成与核验依旧使用完整原文。模型/提示词/温度/超时与是否启用规划都由激活版本控制；并发规划调用有总量上限，检索环节按墙钟计时并统计全部已知模型 Token。

升级时必须从当前协议的可执行基线导出，导入为新版本，再显式激活；旧协议只能展示历史记录，不能直接交给新引擎重跑。可回滚到同协议的旧配置或关闭规划，不能自动切换生产配置。此能力默认关闭，复测库通过导入/激活启用。仍不在线修改代码或 MCP 绑定。

新增 `readiness_items` 单独记录维度是否有候选、是否有结论及失败/缺口。空结论和调用失败必须进入最多两轮的质检退回，不能跳过后把其他引用通过当作整体成功。业务问题传入依据生成，维度标题不能被当作额外法律事实或用来猜测汽车专门制度。独立 Judge 只对格式与索引错误纠正一次，合法 no/partial 不重试；原 Judge 判据不变，人工复核继续待核对。

以下为 2026-10-24 的实现说明与历史基线；该轮协议是 `s5-grounded-rules-v2`。详见[上一轮专项记录](../reviews/S5_QUALITY_FOLLOWUP_20261024.md)。其中“纯确定性检索”仅适用于未启用上述规划的模式。

## 原文选择与验证

分析请求包含条款完整原文的编号句段。第一阶段模型选择 `clause_id`、连续的整数 `sentence_ids`和用户事实键，不生成最终引文或规则。服务端截取包含列表导语与限定语的原文连续段，再单独请求模型基于这一份依据生成规则或明确拒绝；看不到其他候选条款或第一阶段草稿。服务端绑定法规、版本、事实原话和原文SHA-256。引文不能跨条款拼接，过短片段不能补字，来源隔离和原有数字、币种、日期校验保留。

报告引用和结论JSON均保存 `sentence_ids`、`quote_start/end`、`source_text_sha256`、`selection_version`。旧引用保持原样，新增字段为空，不追填猜测的来源。中文法律规则由模型提炼；逐字依据保留原语言，完整机器译文仍在法规库单独核对，不能把中文分析当作原文译文。

检索采用同一套国别约束与来源过滤；在原文、当前译文和解析标题建立BM25索引，按业务问题和维度多通道检索、RRF融合。译文和Unicode规范化只用于找候选，最终依据仍是完整原文。法规名、国家码、条号和题号不参与成功特判；当前仍是确定性多语言词法检索，尚非语义召回保证。

分析检索排除已有记录明确标为`irrelevant/out_of_scope`的文件，仍可在法规库查看归档。最新解析版本明确`repealed`时不能退回引用旧版`in_force`正文；`unknown`保留未知标记，不当作已确认有效，也不自动猜成废止。

## 稳定性与失败边界

- S5基线 `temperature=0`，具体模型、提示词、温度、超时仍读取激活工作流的S4白名单配置。
- JSON格式异常最多两次请求；Schema/事实键异常最多两次生成。网络、截断、Schema异常分类记录，已知失败请求Token也计入用量。超时由节点整体时限约束。
- 每阶段请求附实际输出Schema；选择阶段列出本任务可用事实键与候选ID。依据生成的格式和数字错误在同一份原文上最多尝试两次，具体失败与已知用量写入`grounding_calls`；之后仍由原程序再次校验。须分别查看模型初次生成错误与环节交接失败，不能把局部重试描述成模型第一次就正确。
- 依据明确拒绝时，可复用节点原有的两次选择预算重新选证据；与Schema纠错共享预算，不另开无限重试。`selection_retries`保留之前的全部选择、引文和拒绝理由。工作流退回仍最多两轮。评测将重选前后全部分析项计入分母和原标准核验/独立Judge，不用剔除失败尝试来提高指标；另外保存最终分析项偏移以区分尝试与最终产出。
- 证据退回最多两轮，携带具体错误和同一批完整编号原文。不得为凑完整度编造条款。
- 无可用候选法源的维度标记 `source_gap`，可形成 `partial_sample`。已有候选但模型不能给出有效结论，或格式、网络、数字、证据选择仍失败，标记 `analysis_error`，任务失败；保留失败记录和已通过结论，不作为可交付报告导出。
- 修改失败报告的文字会追加版本，并继承 `analysis_failed`，不能通过编辑解锁Word/PDF。
- “程序核验通过”只证明逐字来源与数值约束，不证明法律适用已被人工审定。

输出约束要求每维度提炼至多三条最直接规则，保留主体、触发条件、例外和边界，不复述业务事实，不借其他句子补数值，避免冗长响应截断。有效性未知、来源受损或人工复核待核对的状态均不自动改变。

## 评测口径

冻结题集在 `backend/app/analysis/evaluation_cases.json`：32题，覆盖既定五国与八维度，包含事实、原文定位、原文哈希、官方归档来源和期望结论要点。它是根据归档资料建立的工程来源标注集，未经人工复核，不是人工金标准。埃及受损OCR标注保留问题说明；不解除隔离，不根据跑分修改期望条款。

1. `recall@5`：现有检索流程前五项是否命中期望法规和条款，并用条款ID区分同名文件、附表同号条款及版本。标注对应原文缺失或哈希变化时记为来源漂移，不能静默沿用。
2. 引文忠实度：所有生成结论中，逐字子串、句段选择及数字/金额/日期校验通过的比例，未通过的结论不被提前从分母剔除。
3. 事实一致性：另一次模型请求对“结论＋所选引文”判断是否完整支持，标记 `llm_judged`。`partial`不计支持；判定失败不计成功，单列Judge覆盖率和错误。

没有生成结论时，相应题显示 `0/0`，不是100%；总体面板同时列出题目完成数、各指标分子/分母和人工复核 `0/32`。未生成结论题可从JSON与逐题表定位。期望结论要点供人工核对，不用关键词出现与否冒充事实一致性。

结果由服务端计算，逐题追加到不可变审计表。管理端GET只读，打开看板不触发模型。POST运行评测仅平台管理员可用；不得用客户端提交的分数覆盖结果。一个批次混用配置或未完成时，脚本拒绝发布完整汇总。

## 2026-10-25：原文上下文、语义质检与成本修复

最新工程与实测记录见 [剩余召回、结论支持与成本修复](../reviews/S5_FIDELITY_COST_20261025.md)。本轮隔离环境为数据库 `remediation_s5_fidelity_20261025`、API `18008`、管理端 `5188`，不会覆盖旧环境。

- 续片与起始片段只通过同版本归档重解析建立只读关联，并占用真实 top-k 名额；不靠小数编号猜测，也不合并不同文档/版本的评测身份。
- 语义图谱名称只能帮助寻找候选 ID，不能充当法条依据。复用范围受来源、版本、证据及审批状态隔离。
- 当前执行协议 `s5-source-support-v6`：程序按句号编号提取逐字依据，多句/列表按全部原文单元转述；随后必须通过源文—结论语义质检。引文/数字检查和机器语义质检均不能替代人工法律核验。
- 独立评测仍审阅程序有效但运行时语义质检退回的提案；拒答、无输出、服务错误分别记录，不能从分母隐去。题集、期望条款和独立 Judge 提示词保持冻结。
- 原样保留经再校验的已通过项，只重试失败事实及证据范围；跨条、遗漏、失败修复仍阻断完整报告。原文、审批和历史提案不改写。
- 同作用域、相同源文及配置的成功检索可短期缓存与并发合并；失败不缓存成功。已知 Token、实际新请求与复用来源分开记账，冷运行与连续报告的成本分别比较。

## 官方来源候选与版本比较（v45 / v46）

详见 [官方原文、版本消歧与 OCR 候选记录](../reviews/S5_OFFICIAL_SOURCES_20261025.md)。本轮使用 `remediation_s5_sources_20261025` / API `18009` / 管理端 `5189`，原 v44 数据和服务保留。

`source_identity_observed` 是有原文归档、出处和摘录绑定的受控登记，身份键由来源资料配置提供，非模型自动断定。它仅允许检索器把可能对应的另一份条款纳入同一 top-k 预算供比较，不能合并文档/版本、认定法律效力相同或猜测现行性。章节结构中的合法罗马数字与阿拉伯数字可等值匹配，附表重号或明确不同章节不匹配；没有章节信息时必须保证条号在相应文档内唯一，仍只作比对候选。

新增清晰正文以独立文档/版本保存。法定机构转载标记同时进入模型输入、API、报告正文和两种导出；原报告不回填。未确认有效状态与人工复核仍保持未知/待核对。

OCR 重识别使用原图、逐词坐标、权重哈希和两个分割模式保存完整候选，不使用模型补字。两次 OCR 一致也不等于人工法律批准；本次结果存在差异，只追加未启用的修订提案，不能替换原条款或进入报告。

`register_official_source_candidates.py` 仅向新隔离库登记已归档、robots 允许的来源，拒绝覆盖已有文档；`probe_ocr_source.py` 限页运行并拒绝覆盖旧探测；`verify_s5_preservation.py` 可传独立归档目录，基线按数据库 JSON 类型规范化后逐字段比较，仍拒绝 ID 错绑、重复和任何未留存的改写。

v46 的 `legal-list-coverage-v8` 选证目录把明确引导语后的连续完整法律列表作为单一选证单元，六项选证上限不变；全部原文单元仍逐一覆盖并核对数字，条文边界不跨越。目录只是源文偏移的投影，不重写数据库条款或历史证据。

文档详情的下载登记仅在归档完整性、文档/版本身份、来源 URL、robots 记录和审计哈希绑定后显示；显示来源性质不等于人工批准或现行法确认。对应的用户界面保持只读，无新增模型调用。
